# PR #394: arbitrary local paths and HTTP(S) images

[Fabio's follow-up](https://github.com/pergolafabio/Hikvision-Addons/pull/394#issuecomment-6599461618) reported that the controls seem to work and requested flexible paths/HTTPS and a justified image-size limit. [52ca49d5f84f](https://github.com/giflydimarik-gif/Hikvision-Addons/commit/52ca49d5f84f26f19cef0a31b6e730e6c9cbeba4) removes the fixed directory, reads local container paths or HTTP(S) image bodies, and bounds the image to 512 KiB. No dependencies or add-on config changed.

The [Hikvision indoor SDK guide, section 4.37, printed p. 79](https://git.pyer.club/kingecg/hksdk/raw/branch/main/CH-HCNetSDKV6.1.9.47_build20221111_linux64/%E5%BC%80%E5%8F%91%E6%96%87%E6%A1%A3/%E8%AE%BE%E5%A4%87%E7%BD%91%E7%BB%9CSDK%E7%BC%96%E7%A8%8B%E6%8C%87%E5%8D%97%EF%BC%88%E5%8F%AF%E8%A7%86%E5%AF%B9%E8%AE%B2%E5%AE%A4%E5%86%85%E6%9C%BA%EF%BC%89.pdf) documents 512 KB per JPEG. A read-only capability query of **VDP-H3212W / V2.2.22 build 230720** returned `maxPicNum=6` and `maxSinglePicSize=512` (KB). This PR sends only one optional picture; other firmware may advertise a smaller maximum. The old 24 KiB limit was a conservative prototype bound.

At **2026-11-03 12:13 MSK (09:13 UTC)**, the unchanged PR structs, sender and both MQTT callbacks fetched the [existing public demonstration JPEG](https://raw.githubusercontent.com/giflydimarik-gif/hikvision-asterisk-dect/6eb287032e6f0db7a08aebfe381fce3fda4df803/indoor-notifications/examples/card-preview.jpg) through real HTTPS with normal certificate verification, then made exactly **one accepted native command 16008**, level 4, with one **640 × 360 / 22,524-byte** JPEG. Its SHA-256 matched the existing fixture. Source Git blobs were checked before AST extraction. Field edits neither fetched an image nor sent a notice; only the fresh button callback did so.
